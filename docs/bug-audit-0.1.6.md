# 0.1.6 停用与重载复查记录

日期：2026-11-04。基线：0.1.5。修复版：0.1.6。数据结构继续使用 `decisionReview: 1`，正常记录无需迁移。

本轮在独立真实 Obsidian 1.8.7 中复现并修复一处 P1 设置与命令归属问题，以及两处 P2 边界问题。

| 优先级 | 问题与影响 | 修复 |
| --- | --- | --- |
| P1 | 旧实例的设置请求延迟完成时，插件已经停用并重新启用。新实例选择目录 C 后，旧请求仍将目录 B 写入配置，并重新注册绑定旧实例的命令；界面与持久化目录不一致，后续命令可能写入 B，重载后也会显示 B | 停用实例拒绝后续设置请求；异步步骤完成后再次检查生命周期。同一笔记库的设置持久化跨实例排队，新实例启动先等待已发出的写入结束，旧实例不能再接管命令或界面 |
| P2 | 停用后仍留在屏幕上的旧表单可以保存到原目录，重新启用并换目录也不会使旧表单失效 | 停用立即关闭原存储实例。旧表单和排队请求提交前检查实例状态，拒绝保存并保留输入；重新启用后需要打开新表单 |
| P2 | 启动期间，存储因文件事件已读完，宿主工作区仍未建立。此时打开面板报 `No tab group found.` | 打开工作台、笔记和匹配当前笔记的回访命令先等待宿主布局就绪，随后再次检查实例是否仍有效 |

复现中没有发生源记录删除。目录配置被旧请求覆盖会使重载后的列表指向错误目录，但原目录的 Markdown 文件仍在磁盘上。插件不会自动搬迁这些文件。

## 复现与验证

- `scripts/native-lifecycle-acceptance.py`：0.1.5 在 9 组断言中失败 6 组，确认旧表单继续写入、旧请求覆盖设置、命令被旧实例接管及重载后目录错误；0.1.6 全部通过。新实例的新表单仍能正常保存，既有决定、经验及普通笔记逐字节不变。
- `tests/lifecycle.test.ts`：新增 8 项回归，覆盖关闭实例后的写入、移到回收站、经验及演示操作；创建、更新、移到回收站和重命名在等待读取期间被停用；跨实例设置写入与启动读取的顺序、失败后恢复及不同笔记库互不阻塞。
- 原生目录可见性回归捕获启动错误。当时 `layoutReady` 为 `false`，布局根节点及最近标签页均不存在；等待布局的修复后，恢复文件与打开面板均成功，专项扩为 15 组断言。
- 全量 81 项 Node 自动测试、严格 TypeScript 检查与构建通过。包括生命周期专项在内的 87 组原生回归通过；另完成实际安装 ZIP 的 4 组实装检查，以及源码 ZIP 的干净安装、81 项测试和构建一致性检查。详见 [验收记录](verification.md)。

停用保护针对尚未提交的操作。已交给宿主的文件 I/O 允许完成，不通过回滚或删除补偿中断它；后续写入与界面回调会停止。已发出的设置写入由新实例启动时等待完成，避免新旧实例持久化顺序倒置。

## 更新与恢复

1. 先复制尚未保存的输入。
2. 解压 `decision-review-0.1.6.zip`，替换插件目录中的 `main.js`、`manifest.json` 和 `styles.css`。
3. **完整重载一次 Obsidian**，清除旧版已经留在内存中的表单与回调。仅替换磁盘文件或停用再启用，不能让旧版对象自动获得新保护。

如果此前发生过目录设置回退，在设置中重新选择实际保存记录的可见目录，再重新读取。不要因为列表变空就删除旧目录；本版更新不移动或重写既有数据。
