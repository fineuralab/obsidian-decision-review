# 0.1.1 Bug 检查与修复记录

日期：2026-11-04。检查基线：0.1.0。修复版本：0.1.1。数据格式继续为 `decisionReview: 1`。

本轮先运行原有 40 项测试，再编写失败用例和真实 Obsidian 复现脚本。共确认并修复以下 8 类问题。

| 问题 | 触发与影响 | 修复 |
| --- | --- | --- |
| 经验副本失败重试重复建文件 | 原经验丢失后选择「另存一份」，新文件已保存但来源索引写入失败；再次保存会生成另一个副本，留下孤立文件 | 重试先复用已写入、尚未关联到源决定的同版本经验；独立的主动另存仍使用新路径 |
| 超限保存先写入后报错 | 文件接近读取上限时，追加记录会先落盘，再因超限无法重读，导致界面报错而源文件已经变化 | 生成内容时即执行与读取一致的大小校验，超限在写入前拒绝，保留原文件和表单 |
| 历史回访日期无法更正 | 实际回访日期应晚于当时安排的下次回访日期时，更正沿用了新回访的日期约束，无法保存 | 更正仍校验日期与版本，并强制保留原安排；不再用历史计划限制更正后的发生日期 |
| 循环 YAML 元数据进入索引 | 含自引用锚点的额外属性能通过原校验，随后搜索或修改中的 JSON 序列化会抛错 | 读取和保存前检查数据可序列化性，将异常显示为具体文件问题并禁止覆盖 |
| 切换目录读取失败后界面仍显示旧状态 | 新目录不可读或被文件占用时，内部目录已经变化，但没有发布错误和更新通知 | 统一发布目录读取失败状态；显示新目录错误，清空旧列表，保留旧目录文件 |
| 当前笔记回访匹配遗漏资料 | 资料仅存在于回访更正或补充记录中时，命令没有定位到关联决定，而是弹出更大的候选列表 | 关联匹配包含原记录、修订、回访、更正和补充中的所有文件引用 |
| 搜索遗漏经验标题与来源决定 | 在全部决定中搜经验标题找不到对应决定；在经验页搜来源决定名称也找不到笔记 | 全部决定搜索加入经验标题；经验搜索加入来源决定的原名与修订名称 |
| 保存期间资料改名使控件提前解锁 | 表单已锁定保存时，资料改名重新创建的「移除」按钮仍能点击 | 重建的按钮继承保存锁；失败后恢复当前全部控件，输入继续保留 |
