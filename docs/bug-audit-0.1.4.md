# 0.1.4 隐藏目录复查记录

日期：2026-11-04。基线：0.1.3。修复版：0.1.4。结构版本继续为 `decisionReview: 1`，正常数据无需迁移。

本轮确认一项高优先级的存储可用性问题：路径校验允许点号开头的隐藏目录，而宿主不会索引其中的记录。

## 问题与修复

在真实 Obsidian 1.8.7 中，将数据目录设为 `某目录/.hidden-data` 后保存决定，0.1.3 返回成功，磁盘上存在完整 Markdown 源文件；保存后的列表和重载后的列表均为 0 条，且没有异常提示。

0.1.4 的处理：

- 设置和存储入口拒绝任一部分以点号开头的目标路径，拒绝前不创建记录，不修改已有设置。
- 创建父目录后核对宿主索引，保存新文件后确认索引存在。已有但尚未被索引的目录明确报错，避免用空列表掩盖读取问题。
- 旧配置已指向隐藏目录时，保留实际配置路径，持续显示恢复提示并暂停写入，防止把新记录写入其他默认目录。
- 活动数据目录被移入隐藏位置时，记录实际位置、保留禁写快照，阻止旧草稿和新草稿写入；重载后保护仍在。重新选择可见目录后解除保护。
- 支持普通目录名内的点号和 Unicode。已有文件引用仍按原格式读取，不因数据目录规则变更而改写或拒绝其内容。

本问题导致访问入口丢失，源文件仍保留在磁盘。修复不自动移动或删除用户文件。

- `tests/visibility.test.ts` 的根隐藏目录和嵌套隐藏目录两项，在 0.1.3 上稳定失败，修复后通过；其余覆盖合法目录重载、旧引用保留、不可用目录持续禁写和恢复。
- 最小原生复现确认：保存无报错，物理文件存在，保存前后索引和重载后列表均为空。
- `scripts/native-visibility-acceptance.py` 在旧版原 12 组检查中有 4 组失败；新版全部 14 组通过。旧文件恢复后的原文及其他决定、经验和普通笔记逐字节不变。
- 本轮另验证大小写路径碰撞和通过适配器创建的未缓存文件均不会被覆盖，这两项在基线上也通过。
- 全量 63 项自动化测试、严格 TypeScript 检查与构建、原有真实 Obsidian 回归、安装 ZIP 实装和源码包干净安装复现均通过。详见 [验收记录](verification.md)。

## 更新与恢复

解压 `decision-review-0.1.4.zip`，替换插件目录中的 `main.js`、`manifest.json` 和 `styles.css`，重新加载插件。

如果旧版本已经把记录保存在隐藏目录，通过系统文件管理器显示隐藏文件，将该目录移入 Obsidian 可见位置，再在插件设置中选择该目录。若只是把原数据目录改成了隐藏名称，优先恢复原来的可见名称，以保留现有内部路径引用。

源文件不需要改写格式。选择有效目录后重新读取，确认原记录、历史及自由笔记；如有插件停用或不可用期间发生的资料移动，重新关联失效引用。持续的配置写入失败仍需要先解决宿主的写入问题，再保存目录设置。
