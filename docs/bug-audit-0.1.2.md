# 0.1.2 严重问题复查记录

日期：2026-11-04。基线：0.1.1。修复版：0.1.2。结构版本仍为 `decisionReview: 1`，已有正常数据无需迁移。

本轮重点检查保存与重载、输入边界、冲突保护、失败重试、目录与演示清理，以及损坏文件恢复。确认并修复以下两类问题。

| 优先级 | 问题与影响 | 修复 |
| --- | --- | --- |
| P1 | 更正回访的多行原因中，单独一行包含 `<!-- decision-review:notes -->` 时，该行被直接插入生成正文，形成第二个分隔标记。保存先写入文件，再在重新读取时报错；重载后记录不可读取。导入的多行资料标签也会触发同一问题 | 多行更正说明使用引用块；资料标签只在正文显示时折叠换行，YAML 原文保留。生成文件在实际写入前经过同一个读取解析器，无法读取的内容不会落盘 |
| P2 | 决定文件已经改成自定义名称后，若误删 YAML 中的 `decisionReview` 类型属性，读取会把它当普通笔记忽略，记录从列表中消失且没有提示 | 通过保留的自由笔记标记识别这类损坏文件，显示具体路径；有旧快照时保留并禁写，新会话同样报告错误，修复后恢复 |

第一类是特定有效表单输入可以触发的记录可用性问题，原始与更正文字仍在文件 YAML 内，并非文件内容被删除。第二类要求源文件先发生结构损坏；修复使问题可见并防止后续覆盖。

- 全量 51 项自动化测试、严格 TypeScript 检查与构建通过。
- 原有主流程、异常文件、重复 ID、演示清理、键盘、阅读位置及上一轮修复的真实 Obsidian 回归通过；安装 ZIP 实装与源码干净安装复现检查通过。详见 [验收记录](verification.md)。

## 已受影响文件的恢复

新版阻止再次生成不可读文件，不自动猜测旧文件中多个分隔标记的边界。

- 第一类：在源文件生成的「已更正」说明里，把额外那一行分隔标记改成引用行 `> <!-- decision-review:notes -->`，保留真正的自由笔记分隔行与 YAML 内容，再重新读取。
- 第二类：若确认仅误删本插件格式 1 文件的类型属性，在 YAML 顶层恢复 `decisionReview: 1`，再重新读取。

更新时解压 `decision-review-0.1.2.zip`，替换插件目录的 `main.js`、`manifest.json`、`styles.css` 并重新加载插件。
